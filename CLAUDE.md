# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

This is a **TWRP recovery device tree** for the ZTE Blade A35 Core (codename `P963F10`), a Unisoc `sp9863a`-based device. It is not a standalone buildable project — it is meant to be dropped into a full TWRP/AOSP source tree at `device/zte/P963F10` and built as part of that tree (e.g. via [TWRP minimal manifest](https://github.com/minimal-manifest-twrp) or a similar AOSP-derived source tree). There is no build system, compiler, or test framework inside this repo itself.

The tree was originally generated by SebaUbuntu's TWRP device tree generator and then hand-modified.

## Repository layout

- `Android.mk` — gates inclusion of this device tree's subdirectories on `TARGET_DEVICE == P963F10`.
- `AndroidProducts.mk` — registers `twrp_P963F10.mk` and declares the lunch combos (`twrp_P963F10-user`, `-userdebug`, `-eng`).
- `twrp_P963F10.mk` — the product makefile. Inherits AOSP's 32-bit core/telephony product configs and `vendor/twrp/config/twrp.mk`, then inherits `device.mk`, and sets `PRODUCT_DEVICE`/`PRODUCT_BRAND`/`PRODUCT_MODEL`/`PRODUCT_MANUFACTURER`.
- `device.mk` — product packages: A/B (seamless update) postinstall config, boot control HAL, update_engine/sideload tooling, fastbootd, and gatekeeper/keymaster packages needed to mount and decrypt `/data`.
- `BoardConfig.mk` — the board/hardware config: architecture (`arm`/`armeabi-v7a`), A/B and dynamic-partition layout, boot image header/kernel packing parameters, prebuilt kernel/dtb wiring, partition sizes, Unisoc platform identifiers (`sp9863a` / `s9863a1h10`), and TWRP UI options (theme, screen blank, toolbox).
- `recovery.fstab` — the recovery-mode partition/mount map: AVB partitions, dynamic (logical) `erofs` partitions (system/vendor/product/etc.), Unisoc modem/DSP partitions, factory/ZTE-specific partitions (`persist`, `ztecfg`, `prodnv`), and removable storage.
- `system.prop` — runtime properties for USB controller, file-based encryption, Unisoc keymaster/gatekeeper, and virtual A/B.
- `recovery/root/` — recovery ramdisk overlay: init `.rc` scripts (`init.recovery.common.rc` sets up healthd, USB ConfigFS gadgets, wifi/bluetooth data dirs, snapuserd/servicemanager services) and per-SoC-variant `ueventd.*.rc` files, plus `system/etc/twrp.flags` (extra fstab-like entries used by the TWRP flashable-image UI).
- `prebuilt/` — binary `kernel` (Image) and `dtb.img`, referenced directly by `BoardConfig.mk` via `TARGET_FORCE_PREBUILT_KERNEL`.

## Key device characteristics to keep consistent

- **Platform**: Unisoc `sp9863a`, bootloader board name `s9863a1h10`. Multiple `ueventd.*.rc` variants exist for different SoC sub-revisions (`s9863a1h10`, `s9863a1h10_go`, `s9863a14c10_go`, each with 32-bit variants) — when editing ueventd rules, check whether the change needs to be mirrored across all variant files.
- **Partitioning**: A/B + Virtual A/B with dynamic partitions (`system`, `system_ext`, `vendor`, `odm`, `product`, `vendor_dlkm` under `zte_dynamic_partitions`). `BOARD_SUPER_PARTITION_SIZE`, `BOARD_ZTE_DYNAMIC_PARTITIONS_SIZE`, and the partition list in `BoardConfig.mk` must stay consistent with `recovery.fstab`'s logical partition entries.
- **Recovery-as-ramdisk model**: `BOARD_USES_RECOVERY_AS_BOOT := false` with `TARGET_NO_RECOVERY := true` and recovery resources moved into `vendor_boot` (`BOARD_MOVE_RECOVERY_RESOURCES_TO_VENDOR_BOOT`, `BOARD_INCLUDE_RECOVERY_RAMDISK_IN_VENDOR_BOOT`) — this is a kernel 5.4 vendor_boot-based device, not a legacy standalone recovery partition.
- **Security patch dates are intentionally set far in the future** (`PLATFORM_SECURITY_PATCH` / `VENDOR_SECURITY_PATCH := 2099-12-31`) as an anti-rollback workaround. Do not "fix" these to a real date without understanding why they were changed.
- **Prebuilt kernel/dtb**: sourced from `prebuilt/kernel` and `prebuilt/dtb.img`. If the kernel is updated, both files under `prebuilt/` need to be replaced together, and `BOARD_KERNEL_*` offsets/cmdline in `BoardConfig.mk` should be re-verified against the new kernel's boot image header.
- Copyright headers use `Copyright (C) 2026 The Android Open Source Project` / `SebaUbuntu's TWRP device tree generator` with an `SPDX-License-Identifier: Apache-2.0` tag — follow this header style in any new `.mk` files.

## Building

This repo cannot be built in isolation. To build a flashable TWRP image:
1. Place/symlink this tree at `device/zte/P963F10` inside a TWRP-capable AOSP source tree (e.g. a `minimal_manifest` TWRP tree).
2. `source build/envsetup.sh`
3. `lunch twrp_P963F10-eng` (or `-user`/`-userdebug`)
4. `mka recoveryimage` (or the tree's equivalent target for a vendor_boot-packed recovery image, given `TARGET_NO_RECOVERY := true`).

There are no linters, unit tests, or CI configured in this repository — validate changes by building the image in a full source tree and testing on-device (or checking `.mk`/`.rc` syntax by hand).
